# ESP32-S31

`esp32s31` runs on `esp_soc::Machine` / `Soc` (same path as C3/C6/P4) and is
registered as `--chip s31` / the `esp32sim-s31` binary. It models the S31
peripherals that ESP-IDF v6.1 firmware for the Espressif ESP-Mosaico uses, on two
HP harts: `--board mosaico` has the CO5300 AMOLED, touch, WiFi (WPA2, DHCP), audio,
the IMU and magnetometers, the keys and the motor ([boards.md](boards.md)), on the command
line and in the browser ("In the browser" below). The
original scope proposal was [#319](https://github.com/mikroverk/esp32sim/issues/319).

The implementation was developed in the
[`zhuzhe1983/esp-online-tester` fork](https://github.com/zhuzhe1983/esp-online-tester/tree/58f84135e18c5902e93f33548e0b4bd1e503b4e3/esp32s31).
It is not a source port of Espressif's binary emulator.

## Contract and source versions

The base register source is ESP-IDF v6.1 revision
`fff9895c82d744c7237be8847347bdd1b07c6643`. The later security-clock header layout
also cites revision `274d7ebeaf15cf397347877c34816ea9470d153f`; those differences
are called out in the relevant model. Code comments name the register/header
behind each block. None of these models is silicon-qualified by this contribution.

S31 is not a P4 board alias. Its principal windows are:

| Region | Address interval |
| --- | --- |
| HP SRAM | `0x2f000000..0x2f080000` |
| LP SRAM | `0x2e000000..0x2e008000` |
| ROM | `0x2f800000..0x2f850000` |
| Flash virtual addresses | `0x40000000..0x44000000` |
| PSRAM virtual addresses | `0x50000000..0x54000000` |
| UART0 | `0x2038a000` |

The shared RV32 core supplies its RV32IMAFC subset, Zba/Zbb/Zbs, Zcb/Zcmp, the
Xesploop hardware loops and the subset of PIE (Xespv2p2) that IDF v6.1 firmware uses
(`Cpu::new_esp32s31`), counters and standard CLIC CSR placement (`mintstatus=0xfb1`,
`mintthresh=0x347`). PIE instructions outside that subset decode as illegal. P4's existing
CLIC register/arbitration code is extracted into `esp-periph::clic`; its legacy
and rev >= 3 configuration and behavior remain separate from S31's address map.
S31's interrupt matrix requires an explicit machine-mode PASS_LEVEL.

Two harts interleave through `esp_soc::Machine`. Shared atomic memory, stall/reset
controls and interrupt delivery are functional; this is not measured parallel
execution, bus arbitration or cycle-accurate timing.

## Implemented subset

| Area | Exercised behavior | Boundary |
| --- | --- | --- |
| SRAM, ROM, CPU startup | Mask-ROM load (`Machine::load_rom` / `load_mask_rom`), Flash-MMU `--boot app`, two-hart reset/entry, shared atomics | No instruction substitution; no complete reset-domain machine |
| Interrupts | Local CLIC/matrix (169 sources, dual-core; same choice as S3/P4), UART/USB/timer sources | Modeled sources only; source 152 (EFUSE) outside DeviceSet's 128-bit status |
| UART / USB / timers / eFuse | Shared DeviceSet IP: UART0, Systimer, UsbSerialJtag, TimerGroup, S31 Efuse | No USB enumeration or physical UART/USB timing |
| Flash and PSRAM | Explicit NOR commands/identity/SFDP, erase/program, MMU windows, serial PSRAM and AXI gates | Caller-supplied arrays; functional caches, no cache-line timing |
| Clock/reset/power | XTAL/CPLL/MPLL controls, gated domains, timer counting, watchdog/reset/brownout | Missing analog/clock inputs remain missing |
| USB-OTG HS | The shared DWC2 core (`usb_otg.rs`, P4 HS configuration) at `0x20300000`, source 99, with buffer DMA or in slave mode. A host on the port with `--usb-host`. An Arduino 4.0.0 build with USB mode OTG (TinyUSB, slave mode) enumerates as CDC, HID, MSC and vendor, and its CDC console answers `cdc` commands. In the browser a manifest's `"usb_cdc": true`, or the firmware panel's "USB CDC console" box, does the same ([wasm.md](wasm.md)) | S31 identity and FIFO sizes taken from the P4; no host mode |
| UART1 / UART2 | The shared UART at `0x2038b000` / `0x2038c000`, sources 10 / 11, behind their HP_SYS_CLKRST clock words (0x8c, 0x90) with the same gating and resets as UART0. TX is the `uart1` / `uart2` console, and console input with `src` `uart1` reaches RX. `s31-devkit` wires UART1 TX back to RX | No pin routing, no baud timing, no UART3 |
| RMT | The shared transmitter (`esp_periph::rmt`) at `0x20355000`, source 22: TX channels 0-3 from symbol memory (+0x800), and TX3's DMA from the AHB-GDMA OUT channel on trigger 10, a SUC_EOF node at a time, which IDF's ping-pong ring refills (OUT_LINK RESTART resumes at the stopped descriptor, `ahb_v2.rs`). FastLED's RMT5 driver sends complete frames. Each finished frame goes to the pins whose GPIO matrix output is RMT_SIG_OUT0+n (246+n); `s31-devkit` shows its WS2812 on GPIO 60 and reports frames per pin | No RX channels, no clock gating, no deadline while transmitting (an idle skip finishes the frame at the next wake-up). |
| TWAI (CAN / CAN-FD) | The CTU CAN FD controller (`esp_periph::twaifd`) at `0x20394000` / `0x20395000`, sources 18 / 20, as IDF 6.1.1's `esp_twai_onchip` driver uses it: soft reset, enable (error active at once, FCSI), INT_STAT/ENA/MASK, four TXT buffers with their commands, states and priorities, the 128-word RX buffer read through RX_DATA, mask filters A-C and the range filter, ACK errors with the retransmit limit, TEC/REC and the fault states, the traffic counters, and the STM, ILBP and BMM modes. A sent frame goes to the board (`BoardModel::can_frame`), which ACKs it and may answer. `s31-devkit` has a CAN node on TWAI0 that ACKs, echoes and answers OBD-II PIDs | A frame takes no bus time (it completes at the next tick); no bit timing, timestamp timer, arbitration, or bit/stuff/CRC errors, no clock gating, no pin routing |
| SAR ADC | One-shot conversions at `0x20815000` (`adc.rs`): the channel from SARn_PATT_TAB1, TRIGGER_START converts at once, DONE in INT_RAW (bit 31 ADC1, 30 ADC2), the code in SARn_DATA_STATUS. ADC1 is GPIO 42-49, ADC2 from GPIO 50. A pin's voltage comes from a script's `adc PIN VOLTS`, `--adc-raw`, or the run page's analog input (`{"t":"adc"}`) | The C6's 12-bit curve at 12 dB (the S31's coefficients are not public), no conversion time, no continuous/DMA mode, thresholds, filters or interrupt line |
| GPIO | Local pads / IO_MUX / LP+HP hold — shared `Gpio` blocked (ENABLE@0x34, IN@0x64, PIN@0xf4, OUT_SEL@0xaf4, 62>57 pins + hold coupling); see `pads.rs` | No complete peripheral pin matrix |
| LEDC | LEDC0/LEDC1 (`ledc.rs`): the duty in effect, duty updates and hardware fades through the gamma ranges, timed from the channel's timer and the HP_SYS_CLKRST source clock, DUTY_CHNG_END on sources 31/32; a routed pin is on while the duty is above zero | No waveform (a pin is on or off), HPOINT, overflow counter, ETM |

An access no model claims inside the peripheral window (`0x2000_0000..0x2100_0000`) does not
fault. A read returns the last value written there (0 at first), and the end-of-run report lists
the registers and, per 4 KiB block, how many (`unmodelled registers by block`). Outside that window,
unknown accesses and missing required inputs report a typed fault with the guest PC. Recognized controls do not imply that every register in the same block works.

## CLI

```sh
# Exact hello path (ROM + IDF v6.1 images from tools/fetch-s31-firmware.sh):
esp32sim-s31 --boot rom \
  --rom path/to/esp32s31_rev0_rom.elf \
  --bootloader esp32s31/firmware/s31-hello-bootloader.bin \
  --ptable esp32s31/firmware/s31-hello-ptable.bin \
  --app esp32s31/firmware/s31-hello_world.bin \
  --max-insns 8000000000
# Equivalent: esp32sim --chip s31 --boot rom ...
# App-only (skip mask ROM, Flash MMU map): --boot app
# ROM also via tools/fetch-rom-elfs.sh DIR (esp32s31_rev0_rom.elf, esp-rom-elfs 20260528).
```

Default flash is 2 MiB with `BoardInputs::hello_w25q16` (JEDEC `0xef4015`) and
strap `0x10` (SPI_FAST_FLASH_BOOT). Override with `--flash-mb`, `--strap`.

## IDF hello_world

**Upstream acceptance target:** ESP-IDF **v6.1** `hello_world` built with
`idf.py --preview set-target esp32s31`, run through `--chip s31 --boot rom`
(or `esp32s31::Machine`). See `tools/fetch-s31-firmware.sh` and
[the contribution receipt](evidence/s31-upstream/README.md).

`Cpu::new_esp32s31` defaults `ext_ill_all_fp` so FS-Off FLW/FSW set
`EXT_ILL.FPU`, matching IDF v6.1 S31 (and P4 rev ≥ 3) lazy-FPU handling.
Observations that informed the default came from the **Apache-2.0**
Espressif esp-emulator 0.51.0 used as an observable oracle only (no source port).
Legacy SPI0 length words used by the 20251218 mask ROM are enabled automatically
when the ROM image is loaded (no CLI flag).

Golden (ignored by default):

```sh
tools/fetch-s31-firmware.sh
S31_ROM_ELF=…/esp32s31_rev0_rom.elf cargo test -p esp32s31 --release --test hello_golden -- --ignored
```

The public ROM is from Espressif's
[20260528 ROM ELF archive](https://github.com/espressif/esp-rom-elfs/releases/download/20260528/esp-rom-elfs-20260528.tar.gz)
(Apache-2.0). Archive SHA-256
`caa463d3cbef2430a5a35847c1d9f2f152403b17a802050927ff60c8da54fe46`;
`esp32s31_rev0_rom.elf` SHA-256
`a52ad7513deb656a910a5740125f1cce2c7941f11ce57213b7b43aea93d5ab87`.

## In the browser

The WebAssembly module builds the S31 for the board names `esp32s31` (a bare module: 2 MiB of
flash with the hello image's W25Q16 identity, as the CLI's default) and `mosaico` (the
ESP-Mosaico: `BoardInputs::mosaico_gd25q128`, its 16 MiB of PSRAM in package and eFuse board
revision, and the board model with its panel, touch, keys, motor and sensors). The page fetches
`esp32s31_rev0_rom.elf` for both (`tools/fetch-rom-elfs.sh`, as for the other chips) and paces
the run against 320 MHz. The page's PSRAM field does not apply: the S31's PSRAM is the board's.

The demo `s31-mosaico` (`web/wasm/fw/s31-mosaico.json`) boots `examples/mosaico-demo`, LVGL
through esp-mosaico-bsp on the Mosaico's round panel, with the board's scripted handling
(`imu_motion: 1`) turning the IMU and both magnetometers; see [boards.md](boards.md) (`mosaico`)
and [wasm.md](wasm.md) for what it shows and how fast it runs. CI boots it under Node
(`tools/wasm-test.mjs s31-mosaico`), and `wasm/tests/abi.rs` drives it through the page's ABI
(touch and the AI button included).
